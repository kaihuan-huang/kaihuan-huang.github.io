05Engineering notes工程记录

Five repositories, one engineering contract五个仓库，一套工程契约

2026-10 · Merged in all five, deploy pending五个都已合并，部署待定

What exactly did you own?你具体负责哪部分？
I wrote and merged all five PRs. Before merging, I replayed the full merge order on throwaway databases in strict mode. One rule decided each merge. Only a blocker stops it, and anything else gets an owner and a plan. The repository that touched live bookings went last.
Why not one shared package?为什么不做成一个共享包？
The contract was shared, but the code was not the same. Each service needed a different change, and one of the five is not even Python. A shared package would also have forced a dependency upgrade across the four services first, and tied their releases together. So I shared what was identical. One migration-adoption tool, one script that checks every service against the contract, and one merge gate. The cost is that small pieces such as config parsing live in four places, and the shared checks catch drift there.
Didn't the stricter defaults break existing clients?更严的默认值，不会弄坏现有客户端吗？
Yes, that was the main risk. The chat API and its web client had to change together, so I merged the client first, and the API change two days later.
Why migrations only?为什么只允许走迁移？
Services could create tables at startup, outside migrations, so a database could drift from the code. In the merged code, startup refuses a database that is not at the latest migration, and a clean database rebuilds from migrations alone. The cost is slower schema changes and a rollback that must go in order. Downgrade the database first, then roll back the image. I rehearsed that order.
Did strict mode find real bugs?严格模式找到真 bug 了吗？
One small handler bug, and the fix is merged. The other failures were tests written for the earlier defaults.
Is it in production?上生产了吗？
It is merged to main in all five repositories; deploy is pending. Each database needs its own migration step first, and I documented those steps.

ModelGateway: designed before it is builtModelGateway：先设计，还没写

2026-10 · Design only, no code yet只有设计，还没有代码

Is ModelGateway built?ModelGateway 做出来了吗？
No. I designed it in October 2026 and it is a later phase. The data foundation comes first, because an agent reading numbers nobody trusts is worse than no agent.
Why not just use LiteLLM or OpenRouter?为什么不直接用 LiteLLM 或 OpenRouter？
In the design the gateway is thin. It owns policy, meaning tiers, budgets, fallback, privacy and logging. Transport stays open source. The first adapter would be the OpenAI Agents SDK pointed at a local model, and a library like LiteLLM could become a second adapter. The cost is that vendor-specific features such as prompt caching would have to go through an adapter.
What happens when a paid tier fails?付费档挂了怎么办？
Every task would declare its policy. Fall back to local, ask the user, or fail closed. A request that explicitly asks for the strongest tier never downgrades silently. For an owner's decision, a clear error beats a cheap wrong answer.
How does the privacy filter work?隐私过滤怎么做？
In application code, not in prompts. A field allowlist and aggregation come first. A PII detector is only a backstop, because detectors miss things.
How will you know the local model is good enough?怎么知道本地模型够用？
A 40-question eval would gate the build. At least 90% correct tool calls, zero rule violations and 4 of 4 privacy cases. Paid tiers would run the same eval by replaying recorded runs, so testing costs nothing.

The loop in practice: check-in states, Nalu, the POS split循环的实践：签到状态、Nalu、拆 POS

2025 — 2026 · Check-in live · Nalu in pre-launch testing · POS in progress签到已上线 · Nalu 预发布测试 · POS 还在做

Give me an MVP you took to a stakeholder and then changed.举一个拿给干系人之后改掉的 MVP
Reservation check-in. The first version only marked a guest checked in. The owner wanted early arrivals warned, late arrivals held for the host's approval, and a friendly message at the end. We revised the states and the wording six times in three days. What I took from it was to write the rules as a table with the owner before coding. The next contract we did that way.
A round that changed your direction?哪一轮改了方向？
The booking agent. We let a model fill booking fields. In a 30-case pilot only 17 were fully correct and 3 had values the guest never said. I did not fix that with prompting. Booking fields moved to deterministic code, and nothing is written until the guest says yes to the exact summary. On a separate 39-case held-out set, 33 were fully correct and none invented. The cost is one more confirmation step for the guest. The two sets are different cases, so I don't present them as a before-and-after.
What if the stakeholder disagrees with your MVP plan?干系人不同意你的 MVP 怎么办？
A stakeholder wanted the whole POS delivered in one go. I didn't think that was possible safely. I proposed small pieces we could build and test one at a time, then merge. My piece was the settlement path. Four writes became one transaction, with an integration test against a real database that checks a refused capture leaves the order open with no writes. The cost is that it isn't all delivered yet. It's still in progress.
Isn't the loop slower? When did skipping it cost you?循环不是更慢吗？跳过它吃过亏吗？
The loop costs more check-ins and a slower first "complete" version. What it buys is no big-bang rewrite. I learned that the other way. At my first startup every merge auto-deployed with no tests, it only ever ran as a demo, and we missed an investor demo date because we had committed to more than two people could build. Now I plan to the team we have, then commit to a date.

The exit test goes into the plan first退出测试先写进计划

2026-10 · Three pieces merged · exit test not reached底座三块已合并 · 退出测试未达到

How do you know the MVP is right and it's time to scale?怎么知道 MVP 对了、该放大了？
The exit test goes into the plan before the build. For the growth system it says at least one real action recommended and approved, measured against a control group or holdout, incremental contribution profit above zero, no platform-reported attribution, sustained for three months. The first pieces of the data foundation are in place. We have not passed that test yet, so the agent layer waits. For the booking agent the test was a held-out case set.

Rules I tuned on evidence, not taste用证据调规则，不凭感觉

2026-10 · Gate hook live since Oct 27 · approval rule written into each project plan闸门钩子 10-27 起生效 · 审批规则写在各项目计划里

Hooks, not prompts. Why?为什么用钩子不用提示词？
A prompt is advice; a hook is enforcement. In auto mode an "ask" gets approved silently, so the gate exits with an error instead and the blocked action comes back to me. A table-driven test with 168 cases means removing any rule fails a test.
How did you notice the stall?怎么发现卡住的？
By counting. One repo had 87 local commits nobody could see; another had five finished branches waiting days for a merge. Both waited on the same rule. The plans now free pushing and draft PRs, and the backlog became one branch.
Isn't this just process overhead?这不就是流程负担吗？
It is friction, and I measure it. When subagents were 46% of usage I cut their default tier. When the push rule hid finished work, I loosened it. A rule that costs more than it catches gets changed, with the evidence written next to the change.
